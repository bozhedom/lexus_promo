# Промо-воронка «Персональный пригласительный»

Посетитель вводит госномер, автомобиль определяется по внешнему API, дальше
гость оставляет имя и телефон и получает именной пригласительный с подарком.
Пригласительное приходит картинкой в Telegram, MAX или WhatsApp.

С первого экрана расходятся две ветки:

- **приглашение** — `/car-number` → `/car-info` → `/personal`;
- **запись в сервис** — `/booking/car-number` → `/booking/car-info` →
  `/booking/appointment`.

Экраны номера и автомобиля общие, ветку им передаёт страница (`flow`), маршруты
лежат в `src/shared/lib/flow.ts`.

**Стек:** Next.js 16 (App Router), React 19, TypeScript, Payload CMS 3,
PostgreSQL 16, SCSS-модули.

## Запуск

Нужны Node 20+ и Docker.

```bash
cp .env.example .env
```

В `.env` заполните `PAYLOAD_SECRET` (`openssl rand -hex 32`) и
`PAYLOAD_ADMIN_EMAIL` / `PAYLOAD_ADMIN_PASSWORD`. Остальное для локальной работы
уже проставлено.

```bash
npm install
npm run db:up
npm run setup
npm run dev
```

Сайт — http://localhost:3000, админка — http://localhost:3000/admin.

Три варианта QR-ссылок для первого экрана: `/?toyota` — только Toyota,
`/?lexus` — только Lexus, `/` — обе марки вместе.

## База, миграции и данные

`npm run db:up` поднимает Postgres 16 в докере. База живёт в томе
`promo_pgdata` и переживает перезапуск: `npm run db:down` останавливает
контейнер, данные при этом остаются.

`npm run setup` — три шага одной командой, и его же достаточно на чистой базе:

| Шаг | Что делает |
| --- | --- |
| `npm run migrate` | накатывает схему Payload из `src/migrations` |
| `npm run admin:reset` | заводит аккаунт админки из `.env` |
| `npm run seed:car-photos` | переносит встроенные кадры в раздел «Фото автомобилей» |

Схема набирается миграциями по порядку из `src/migrations/index.ts`. Кадры
пригласительных переносит миграция `20260813_190000_car_photos_seed`; отдельный
скрипт `seed:car-photos` нужен там, где схему подняла разработка и до миграций
дело не дошло. Оба идемпотентны — непустой раздел они не трогают.

Остальной контент (слайды автоцентра, суммы сертификатов, каталог марок, тексты
сообщений) отдельного сида не требует: в коде лежат значения по умолчанию, а
менеджер правит их в админке. Подробности — в [docs/content.md](docs/content.md).

Загрузки Payload лежат в папке `media/` рядом с проектом, а не в базе. Её нужно
класть в бэкап вместе с дампом Postgres.

## Команды

| Команда | Что делает |
| --- | --- |
| `npm run dev` | дев-сервер |
| `npm run build` / `npm start` | продакшен-сборка и запуск |
| `npm run db:up` / `npm run db:down` | локальный Postgres в докере |
| `npm run setup` | миграции, аккаунт админки и кадры разом |
| `npm run migrate` | накатить миграции Payload |
| `npm run admin:reset` | сделать аккаунт из `.env` единственным аккаунтом админки |
| `npm run seed:car-photos` | перенести встроенные кадры в админку |
| `npm test` | юнит-тесты (vitest) |
| `npm run e2e` | прогон воронки в браузере со скриншотами (`npm run e2e -- 320 568 se1`) |
| `npm run lint` | eslint |
| `npm run tunnel` | публичный HTTPS-адрес для вебхуков мессенджеров |

## Переменные окружения

Все описаны в `.env.example`. Обязательные — `DATABASE_URL` и `PAYLOAD_SECRET`.
Без `CAR_API_URL` определение авто по номеру выключено, и воронка сразу просит
заполнить марку и модель вручную. Без `NEXT_PUBLIC_YM_ID` не подключается
счётчик Яндекс.Метрики.

Переменные с префиксом `NEXT_PUBLIC_` попадают в сборку и меняются только
пересборкой: правка в `.env` без `npm run build` до браузера не доедет.

## Структура

```
src/
  app/(frontend)   страницы воронки
  app/(payload)    админка
  app/api          эндпоинты воронки
  views/           экраны
  widgets/         крупные блоки (галерея, пригласительный, занавес)
  features/        ввод госномера, сохранение контакта
  shared/          ui-кит, конфиг, утилиты, аналитика
  invite-test/     выдача и доставка пригласительных в мессенджеры
  collections/     коллекции Payload
  lib/             серверная логика: валидация, внешний API, рейт-лимит
  migrations/      миграции базы
```
