# Доставка пригласительных (`invite-test`)

Модуль выдаёт гостю два персональных сертификата картинками и доводит их до
**живого диалога с менеджером**, куда сертификаты прилетают автоматически от
его имени. Дальше идёт обычная переписка и продажа.

Отдельной демо-страницы `/invite-test` больше нет: модалка встроена в воронку
на экране «Команда автомобиля» (`/certificate`) — кнопка «Скачать
пригласительный» открывает её, внутри превью сертификатов, «Скачать на телефон»
и мессенджеры. Имя каталога сохранено, потому что по этим же путям
зарегистрированы вебхуки Telegram, MAX и GREEN-API.

## Что где лежит

```
src/invite-test/
  api/                     фетчеры для браузера
  config/                  переменные, тексты сообщений, список сертификатов
  model/                   типы и хук доставки
  server/                  API Telegram, MAX и WhatsApp, отрисовка картинок, сессии
  ui/                      модалка и кнопки мессенджеров
src/app/api/invite-test/   маршруты API и вебхуков
public/invite-test/        иконки мессенджеров
```

Клиент GREEN-API — `server/green.ts`, один на все три канала. Сами сертификаты рисует `server/certificateImage.tsx`: 1080×1920, кадр
автомобиля подбирается по марке, модели и году (`shared/config/car-photos.ts`),
шрифты — `public/fonts/*.ttf`. Формат 9:16 выбран под мессенджеры.

Нарисованные картинки сохраняются в админку (`server/certificateStore.ts`):
при выдаче кода они попадают в поле «Пригласительный» у соответствующего
сертификата заявки, и в мессенджеры уходят ровно эти файлы. Менеджер в карточке
заявки видит то же, что пришло гостю в чат.

Формулировки сообщений живут в админке, раздел «Тексты сообщений»
(`src/globals/MessageTemplates.ts`): текст, который отправляет гость, текст,
который приходит вместе с пригласительными, и текст записи на сервис.
Подстановки — `{name}`, `{car}`, `{plate}`, `{amount}`, `{code}`; строка, где
все подстановки пустые, из сообщения выпадает. Пустое поле означает «взять
текст по умолчанию» из `config/certificates.ts`, поэтому очищенный раздел
возвращает исходные формулировки.

## Как это работает

Основной путь у всех трёх мессенджеров один — **инстанс GREEN-API**. У сервиса
отдельные продукты под WhatsApp, Telegram и MAX, но REST у них общий
(`{apiUrl}/waInstance{id}/{метод}/{token}`), поэтому клиент в
`server/green.ts` один на три канала, а от настройки требуются одни и те же
три поля: `idInstance`, `apiToken`, `apiUrl`.

Инстанс привязан к личному аккаунту менеджера, так что пригласительные
приходят гостю прямо из диалога с человеком — ни бота, ни Telegram Business
не нужно.

1. Страница просит у сервера короткий код, например `LYJ7PW`.
2. Клиент жмёт кнопку мессенджера. Открывается диалог с менеджером — его имя,
   его фото — и уже подставленный текст: «Здравствуйте! … Код: LYJ7PW». В MAX
   подставить текст в чужой диалог нельзя, поэтому там он уезжает в буфер
   обмена, а страница просит его вставить.
3. Клиент делает один тап «Отправить».
4. Входящее прилетает вебхуком `/api/invite-test/green/webhook`. Вебхук общий:
   канал определяется по `idInstance` в теле запроса.
5. Достаём код, находим сессию и отправляем в тот же чат три сообщения: два
   сертификата методом `sendFileByUrl` и текст отдельным `sendMessage`.
6. Менеджер открывает телефон и продолжает разговор в этом же диалоге.

### Почему клиент всё-таки делает один тап

Ни одна платформа не даёт написать первым человеку, который с вами не
контактировал. Поэтому первый шаг всегда за клиентом — мы лишь свели его к
одному нажатию по готовому тексту.

### Запасной путь: боты

Пока инстанса GREEN-API для канала нет, работают боты — Telegram и MAX. Они
включаются автоматически и так же отвечают на код, но уже от имени бота, а не
менеджера. Как только инстанс заведён, бот для этого канала не используется.

**Telegram-бот.** Кнопка ведёт диплинком `t.me/<bot>?start=<код>`; гость жмёт
«Начать», Telegram присылает нам `/start <код>`, бот отвечает сертификатами и
кнопкой «Написать менеджеру». Если менеджер подключит бота в Настройки →
Telegram Business → Чат-боты, ответ пойдёт от его имени: идентификатор
подключения приходит апдейтом `business_connection`, его же можно закрепить в
`INVITE_TEST_TG_BUSINESS_ID`.

**Бот MAX.** Диплинк `max.ru/<bot>?start=<код>`, гость жмёт «Начать», бот
присылает сертификаты. Отвечает он от имени организации, а не менеджера.

## Что нужно от вас

| Что | Зачем | Обязательно |
| --- | --- | --- |
| Инстанс GREEN-API на канал (`idInstance`, `apiToken`, `apiUrl`) | Принимает код и шлёт пригласительные от имени менеджера | да |
| Аккаунт менеджера, авторизованный в этом инстансе | Гость пишет человеку и от него же получает пригласительные | да |
| Домен с HTTPS и валидным сертификатом | Мессенджеры должны достучаться до вебхука и картинок | да |
| `@username` аккаунта в MAX | Ссылка на диалог: у MAX она только по username, а из инстанса username приходит не всегда | для MAX |
| Токен Telegram-бота и бота MAX | Запасной путь, пока инстанса на канал нет | нет |
| Фотография Toyota на подъёмнике под сертификат | Сейчас для обеих марок берётся кадр из Figma | желательно |

Без инстансов и домена страница тоже работает: кнопки открывают диалог с
менеджером, но пригласительные он отправляет руками.

Токены присылайте не в переписке, а любым секрет-хранилищем, либо заведите
переменные на сервере сами.

## Шаг 1. Домен и HTTPS

Вебхук — адрес, на который Telegram стучится сам, поэтому он должен быть
доступен из интернета по HTTPS с доверенным сертификатом. Самоподписанный не
подойдёт.

```
NEXT_PUBLIC_SITE_URL=https://ваш-домен.ru
```

Для проверки с машины разработчика поднимите туннель и временно подставьте его
адрес в ту же переменную:

```bash
npm run tunnel
```

Команда печатает адрес вида `https://имя.trycloudflare.com`. Дев-сервер
подхватывает правку `.env` сам, перезапускать его не нужно. Адрес живёт, пока
запущен `cloudflared`, и меняется при каждом запуске — после перезапуска нужно
заново прописать переменную и вызвать `/setup` из шага 6.

## Шаг 2. Бот

1. Напишите [@BotFather](https://t.me/BotFather), команда `/newbot`, задайте
   имя и username.
2. Полученный токен вида `123456789:AA...` — это `INVITE_TEST_TG_BOT_TOKEN`.
   Больше от Telegram ничего не нужно: username бота, по которому собирается
   ссылка на чат, мы спрашиваем у `getMe` по этому же токену.
3. Придумайте случайную строку для `INVITE_TEST_TG_WEBHOOK_SECRET`, например
   `openssl rand -hex 16`. Telegram будет присылать её в заголовке, чужой
   запрос на вебхук отсеется.

Имя бота нигде не показывается: клиент его не увидит.

## Шаг 3. Подключить бота к аккаунту менеджера

На телефоне менеджера: **Настройки → Telegram Business → Чат-боты**, указать
username бота и разрешить ему отвечать на сообщения.

По актуальной документации Telegram подключённые бизнес-боты доступны и без
Premium. Если пункт не виден в конкретном клиенте, обновите приложение и
проверьте доступность функции на этом аккаунте.

У менеджера должен быть публичный `@username`, иначе ссылка `t.me/...` не
работает. Он же идёт в `INVITE_TEST_TG_MANAGER` (без «@»).

## Шаг 4. MAX

MAX теперь имеет официальный Bot API. Здесь используется диплинк
`max.ru/<bot>?start=<code>`: клиент открывает чат и нажимает «Начать», MAX
присылает `bot_started` с кодом сессии, после чего бот одним сообщением
отправляет персональный текст и два сертификата.

1. На [платформе MAX для партнёров](https://business.max.ru/) создайте и
   верифицируйте профиль организации, ИП или самозанятого.
2. Создайте чат-бота, дождитесь модерации и скопируйте токен — username, как и
   в Telegram, достаётся по нему.
3. Сгенерируйте секрет вебхука длиной от 5 символов, только из латинских букв,
   цифр, `_` и `-`.
4. Заполните `INVITE_TEST_MAX_BOT_TOKEN` и `INVITE_TEST_MAX_WEBHOOK_SECRET`,
   затем вызовите общий `/setup` из шага 6.

Важное отличие от Telegram: MAX Bot API отвечает от имени бота организации,
а не от имени личного аккаунта менеджера. Чтобы менеджер продолжал этот же
диалог вручную, подключите к боту поддерживаемую MAX чат-платформу или CRM.
Неофициальный скрипт от личного аккаунта в модуль не добавлен: он хрупкий,
требует хранить пользовательскую сессию и создаёт риск блокировки рабочего
аккаунта.

## Шаг 4б. WhatsApp

WhatsApp работает без Meta через QR-инстанс GREEN-API. Номер остаётся в
обычном приложении WhatsApp Business менеджера, а GREEN-API подключается как
связанное устройство. Клиент пишет первым по `wa.me`, webhook передаёт текст и
ID этого же чата, сервер отправляет туда два сертификата. Менеджер продолжает
общение с телефона в том же диалоге.

1. Зарегистрируйтесь в [GREEN-API](https://green-api.com/) и создайте инстанс
   на бесплатном тарифе «Разработчик».
2. В кабинете откройте QR. На телефоне менеджера: WhatsApp Business →
   Настройки → Связанные устройства → Привязка устройства — отсканируйте QR.
3. Скопируйте `idInstance`, `apiTokenInstance` и `apiUrl` в переменные ниже.
4. Сгенерируйте отдельный `INVITE_TEST_WA_GREEN_WEBHOOK_TOKEN`.
5. Заполните номер менеджера в международном формате без плюса
   (`79991234567`) и вызовите общий `/setup`. Он сам пропишет защищённый
   webhook и включит входящие уведомления.

Это QR/Web-клиент, а не официальный Meta Cloud API. Для теста используйте
отдельный номер, отвечайте только на входящие сообщения и не делайте рассылок:
WhatsApp может отключить связанное устройство или ограничить аккаунт.

## Шаг 5. Переменные окружения

```
NEXT_PUBLIC_SITE_URL=https://ваш-домен.ru

# по три поля на канал, из консоли console.green-api.com
INVITE_TEST_WA_GREEN_INSTANCE_ID=7103000000
INVITE_TEST_WA_GREEN_API_TOKEN=...
INVITE_TEST_WA_GREEN_API_URL=https://7103.api.greenapi.com

INVITE_TEST_TG_GREEN_INSTANCE_ID=4100000000
INVITE_TEST_TG_GREEN_API_TOKEN=...
INVITE_TEST_TG_GREEN_API_URL=https://4100.api.green-api.com

INVITE_TEST_MAX_GREEN_INSTANCE_ID=
INVITE_TEST_MAX_GREEN_API_TOKEN=
INVITE_TEST_MAX_GREEN_API_URL=

# общий на все инстансы
INVITE_TEST_GREEN_WEBHOOK_TOKEN=случайная-строка

# Для личного аккаунта MAX вставьте ссылку из «Профиль → QR → Поделиться».
# Она имеет вид https://max.ru/u/.... По номеру профиль открыть нельзя; если
# временно указать номер, откроется «Поделиться в MAX» с готовым текстом, где
# гостю нужно выбрать чат менеджера.
INVITE_TEST_MAX_MANAGER=https://max.ru/u/ссылка-профиля

INVITE_TEST_SETUP_KEY=ещё-одна-случайная-строка
```

Дев-сервер подхватывает правку `.env` сам; на боевом приложение нужно
перезапустить.

## Шаг 6. Прописать вебхук

```bash
curl -X POST "https://ваш-домен.ru/api/invite-test/setup?key=ЗНАЧЕНИЕ_SETUP_KEY"
```

Адрес вебхука у всех инстансов один — `/api/invite-test/green/webhook`, канал
определяется по `idInstance` в теле. В ответе по каждому настроенному каналу
придут состояние инстанса, статус регистрации вебхука и номер аккаунта, к
которому инстанс привязан. Отдельными полями `telegramBot` и `maxBot` —
результаты запасного пути, если он вообще включён.

Снять вебхуки:

```bash
curl -X DELETE "https://ваш-домен.ru/api/invite-test/setup?key=..."
```

## Шаг 7. Проверка

1. Пройдите воронку до экрана «Команда автомобиля».
2. Нажмите «Отправить в мессенджер» → нужный мессенджер.
3. Откроется диалог с менеджером с готовым текстом. Нажмите «Отправить».
4. В ответ придут два пригласительных — из того же диалога.
5. У менеджера в приложении открыт этот же диалог, он отвечает как обычно.

### Проверка без боевых аккаунтов

- UI и формирование ссылок можно проверить обычным браузером: кнопки откроют
  web-страницы мессенджеров даже без установленных приложений. Это не проверяет
  реальную доставку.
- Серверная логика MAX проверяется без аккаунта командой
  `npx vitest run tests/invite-test-max.test.ts`: API подменяется моком,
  тест сверяет получателя, персональный текст, обе картинки и вебхук.
- Telegram можно частично проверить с обычным личным аккаунтом и бесплатным
  ботом BotFather; для ответа именно от имени менеджера понадобится доступная
  на аккаунте функция подключения бизнес-бота.
- GREEN-API даёт бесплатный инстанс «Разработчик» для трёх тестовых чатов;
  подключайте его по QR к отдельному тестовому номеру.
- Полный end-to-end тест без аккаунта невозможен: событие старта/сообщения и
  фактическую доставку подтверждает только сама платформа.

## Известные ограничения

- **Сессии живут в памяти процесса.** Ради тестового модуля не заводили
  коллекцию Payload и миграцию. Код действует час и перестаёт работать при
  перезапуске сервера, а при нескольких инстансах приложения нужен общий стейт
  (Redis или таблица в базе). То же касается `business_connection_id` — его
  можно закрепить переменной.
- **Один менеджер.** Распределения клиентов по нескольким менеджерам нет:
  переменная одна. Для очереди понадобится список аккаунтов и правило выбора.
- **Код виден клиенту** в его собственном сообщении. Формулировка правится в
  админке, раздел «Тексты сообщений»; тексты по умолчанию лежат в
  `src/invite-test/config/certificates.ts`. Слово «Код:» перед кодом лучше не
  убирать: без него код всё равно распознаётся по своему алфавиту, но менее
  надёжно.
- **В MAX текст в чужой диалог не подставляется.** У мессенджера есть только
  два диплинка с текстом: `max.ru/:share?text=` — там чат выбирает сам гость, и
  `max.ru/<бот>?start=` — там это бот, а не менеджер. Ссылка на профиль
  менеджера текст не принимает, поэтому страница кладёт сообщение с кодом в
  буфер обмена и пишет гостю, что его осталось вставить. Полностью без
  вставки MAX работает только через бота — заведите
  `INVITE_TEST_MAX_BOT_TOKEN`, но отвечать тогда будет бот организации.
- **Wordmark Toyota нарисован шрифтом**, а не фирменным логотипом: в проекте
  лежит только логотип Lexus (`public/images/redesign/lexus-logo.png`).
- **Кадр пригласительного** подбирается по марке, модели и году
  (`shared/config/car-photos.ts`); модели без своего кадра получают кадр марки,
  чужие марки — кадр без шильдиков.
- **Статус отправки страница узнаёт опросом** раз в 2,5 секунды, не дольше двух
  минут. Если клиент ушёл в Telegram надолго, надпись он уже не увидит, но
  сертификаты придут.
- **Инстанс GREEN-API для Telegram и MAX работает от личного аккаунта**
  менеджера, а не через официальный Bot API. Это удобно — гость переписывается
  с человеком, — но платформы такую автоматизацию не приветствуют: заводите
  инстанс на рабочий номер осознанно, отвечайте только на входящие и не делайте
  рассылок. На запасном пути через бота этого риска нет, но и отвечает там бот.
- **В MAX ссылка на диалог только по username или ссылке профиля**:
  телефонного диплинка у мессенджера нет, поэтому `INVITE_TEST_MAX_MANAGER`
  для этого канала обязателен.

## Что проверено

Клиент GREEN-API прогнан на моке:

- канал определяется по `idInstance` в теле вебхука, чужой инстанс и групповой
  чат отбрасываются; для WhatsApp принимаются личные `@c.us`/`@lid`, для
  Telegram и MAX — положительные числовые `chatId`; тип MAX в webhook — `v3`;
- сообщение с кодом → два вызова `sendFileByUrl` на адрес нужного инстанса, в
  тот же `chatId`, подпись на втором файле;
- номер аккаунта берётся из `getSettings.wid` и спрашивается один раз;
- `/setup` включает входящие вебхуки и задаёт токен авторизации;
- вебхук без токена отбивается 401, неверный код блокирует чат после пяти
  попыток, повторное сообщение с тем же кодом ничего не отправляет.

Запасной путь через ботов прогнан на моках Telegram и MAX Bot API:

- код достаётся и из текста менеджеру, и из диплинка `/start`;
- в своём диалоге бот шлёт альбом без `business_connection_id`, в
  бизнес-диалоге — с ним;
- после сертификатов бот даёт кнопку в чат менеджера;
- username бота приходит из `getMe`/`me` и кэшируется, недоступное API выдачу
  кода не роняет.

На боевом API проверены состояния всех трёх инстансов и настройки webhook:
инстансы авторизованы, общий webhook прописан на публичный HTTPS-адрес, картинки
пригласительных по нему отдаются. Фактическую доставку подтверждает только
отправка кода с живого аккаунта.
